# Universal VPS Setup

Интерактивный установщик VPS для Debian 13 / Ubuntu 24.04.

**Файл установщика:** [vps-setup.sh](./vps-setup.sh)

## Запуск

Репозиторий публичный: токен не требуется. Команда выполняется от `root`, при необходимости устанавливает `curl` и CA-сертификаты, устанавливает менеджер и сразу открывает универсальную установку:

```bash
clear; bash -c 'set -e; if ! command -v curl >/dev/null || [ ! -s /etc/ssl/certs/ca-certificates.crt ]; then apt-get update; apt-get -o DPkg::Lock::Timeout=600 install -y --no-remove curl ca-certificates; fi; installer=$(mktemp /tmp/vps-bootstrap.XXXXXXXX); trap "rm -f -- $installer" EXIT; curl -fsSL --connect-timeout 10 --max-time 120 https://raw.githubusercontent.com/djing1e/universal-vps-setup/main/install.sh -o "$installer"; bash "$installer" --install'
```

Это одна команда запуска, а параметры вводятся в терминале: подтверждение состава, SSH-порт, публичный ключ, дополнительные порты UFW, режим fail2ban и UDP-исключения. Вставляйте публичный ключ из `.pub`; приватный ключ не нужен. Enter сохраняет уже установленные валидные ключи. На новой VPS пустой ключ не позволяет продолжить настройку SSH.

`install.sh` загружает `vps-setup.sh` с закреплённого commit, сверяет SHA256 и синтаксис, затем устанавливает `/usr/local/sbin/vps-setup` и команду `/usr/local/bin/vps-setup`. Предыдущий менеджер сохраняется в `/root/vps-setup-backup.*`. Неизвестный файл на месте команды и symlink на месте исполняемого файла требуют ручной проверки. Установка пакетов в универсальном сценарии, CrowdSec и входящих блоклистах ожидает освобождения dpkg до 600 секунд. При таймауте или ошибке зависимости соответствующий шаг останавливается. Файлы блокировок не удаляются, процессы автообновления не завершаются принудительно.

Невозможность установить `curl`, ошибка загрузки, checksum или синтаксиса останавливает запуск.

Для повторного открытия меню:

```bash
clear
vps-setup
```

Загрузчик также принимает `--menu`: установить / обновить файл менеджера и открыть меню, без запуска универсальной установки. Для рабочих серверов фиксируйте URL загрузчика на проверенном commit вместо `main`. Публикация новой версии менеджера не обновляет его файлы на VPS автоматически.

## Навигация

| Раздел главного меню | Для чего |
| --- | --- |
| 1. Универсальная установка VPS | Пакеты → SSH → UFW → базовый BBR/fq и conntrack → автообновления → fail2ban → CrowdSec → AS INPUT → Spamhaus/FireHOL INPUT → TCP C2 DROP → UDP Spamhaus DROP |
| 2. Защита | UFW, fail2ban, CrowdSec, Anti-DDoS, Anti-Abuse, AS-списки, GeoBlock |
| 3. Сеть и ресурсы | NextDNS, IPv6, BBR, RPS, conntrack, XanMod, WARP, Swap |
| 4. VPN-нода | Remnanode, Docker, шейпер, временный probe-сервер |
| 5. Проверить сервер | Статус системы и защит, журналы |
| 6. Обновления | Проверка и обновление движка Guard; отдельно пакеты ОС |
| 7. Отдельные компоненты | Выбор одного компонента, описание изменений, переход к настройке |
| 9. Дополнительно | Подготовка РФ-ноды и очистка |

Универсальная установка предназначена для начальной настройки: **без DNS, XanMod, Anti-DDoS и автоматических банов подписок**. TCP DROP действует по C2-парам IPv4 `IP:порт`; UDP DROP — только по сетям Spamhaus IPv4/IPv6 в исходном направлении соединения. Режимы DROP сохраняются для восстановления при загрузке; временные таймеры автоотключения в универсальном сценарии не создаются. UDP-исключения запрашиваются перед первым включением, `NONE` явно означает отсутствие исключений; ранее заданные исключения сохраняются. Docker и Remnanode устанавливаются отдельно. Перед запуском показывается состав и запрашивается `yes`. При ошибке пакетов, SSH или UFW сценарий останавливается с отчётом; ошибки остальных шагов также отражаются в результате. Это не режим безопасного обновления работающей ноды.

`0` возвращает на один уровень назад, а в главном меню завершает работу. Открытие новых разделов навигации не устанавливает компоненты. Установочные действия показывают область изменений; подтверждения внутри компонентов сохраняются.

Это навигация к существующим модулям, а не автоматический планировщик зависимостей. Старые установщики могут менять текущие настройки. Перед настройкой SSH, DNS, firewall и ядра сохраняйте консольный доступ у провайдера. Обновление с резервной копией и откатом пока реализовано только для движка Guard; обновление пакетов ОС может перезапускать службы.

Подробные переходы и соответствие прежним номерам: [Навигация](docs/navigation.md).

## Разработка

Доработки — через ветки и Pull Request. В `main` находится рабочая версия.

### Remnanode: выбор SelfSteal

VPN-нода → Установка Remnanode → **1) Встроенный установщик** теперь предлагает:

- **1) Caddy 2** — прежняя установка, включая опциональный Cloudflare DNS Challenge.
- **2) Nginx + Certbot** — новая установка SelfSteal на Unix-сокете
  `/dev/shm/nginx.sock`, TLS + PROXY protocol; порт 443 остаётся за Xray.

Для Nginx домен должен указывать на VPS, входящий TCP 80 должен быть открыт
в firewall провайдера и доступен центру сертификации. Установщик разрешает 80/tcp
в UFW; сертификат первоначально выпускается через standalone HTTP-01, затем
Certbot переводится на webroot `/var/www/letsencrypt`. Проверяются TLS/HTTP,
продление `--dry-run` и reload-hook; включается `certbot.timer`.
Для Reality укажите target `/dev/shm/nginx.sock` и `xver: 1`.
OOM watcher остаётся опциональным, logrotate устанавливается в обоих вариантах.

Это установка на свободную ноду: занятые порты 80/443, существующие контейнеры,
Compose-каталог, Certbot renewal или reload-hook приводят к остановке до изменений.
Работающие Caddy/Remnanode не мигрируют и не останавливаются. После частичной
ошибки сохранённый каталог требует проверки; повторная установка его не затирает.

### Сменить домен SelfSteal без переустановки

VPN-нода → Установка / настройка нод → **6) Сменить домен SelfSteal**.
Тот же пункт доступен в **Настройка нод → 3) Сменить домен SelfSteal**.
Введите каталог и новый домен; скрипт определит Caddy/Nginx и покажет план.

- Nginx: временно добавляет новый HTTP-host для HTTP-01, выпускает сертификат
  Certbot, меняет TLS-домен и делает reload. Проверяет продление и создаёт
  отдельный reload-hook. Существующий certbot.timer должен быть enabled/active.
- Caddy: сохраняет Cloudflare API Token и остальные настройки; меняет только
  SELF_STEAL_DOMAIN в Compose и пересоздаёт только Caddy с локальным образом.
  Возможен короткий перерыв SelfSteal. Новый сертификат получает сам Caddy.
- Проверяются TLS с PROXY protocol на Unix-сокете и неизменность ID/времени
  запуска Remnanode. Конфигурация Xray и клиентские подписки не меняются.
- Резервные копии находятся в `/var/backups/vps-selfsteal-domain/` (root-only).
  При ошибке выполняется проверяемый откат. После SIGKILL запись `pending`
  блокирует новую смену до ручной проверки; каталог резервной копии указан
  в выводе. Старые сертификаты и аккаунты ACME не удаляются.

Поддерживаются известные SelfSteal-конфиги встроенного установщика и Nginx
мигратора v5: host network, `/dev/shm/nginx.sock`, одна proxy-служба Compose.
Нестандартные конфиги, отсутствующий сокет или конфликтующие proxy-контейнеры
требуют ручной проверки. Новый DNS/HTTP-01 должен быть доступен до операции.
После смены обновите Reality serverNames/SNI и клиентский хост через панель.
Повторная установка Caddy/Nginx поверх существующего каталога запрещена.

### Восстановление CrowdSec после неполной очистки

Если пакет CrowdSec/Bouncer установлен, но обязательный конфиг отсутствует,
пункт **CrowdSec → Установить** сохраняет оставшиеся конфиги в приватную копию
`/root/crowdsec-config-recovery.*`, затем переустанавливает ту же версию пакета
с `--force-confmiss --force-confold`. Существующие файлы не заменяются.
Symlink/нестандартные пути требуют ручной проверки; пустой или повреждённый
существующий файл автоматически не перезаписывается.

Удаление CrowdSec и полная очистка теперь выбирают только фактически
зарегистрированные dpkg-пакеты, включая Debian `crowdsec-firewall-bouncer`.
Ошибка APT останавливает очистку до удаления каталогов конфигурации и данных.

### TCP C2: устранение дублирующихся правил

В режиме block операции install/restore/update/enable-block оставляют ровно
одно проверенное правило `xtls-c2-block`. При наличии точных дубликатов первое
правило и его счётчик сохраняются, остальные удаляются под блокировкой модуля.
Чужие правила и цепочки не очищаются. Необычная структура правила с этим
комментарием требует ручной проверки. Известная предыдущая версия модуля
может обновляться универсальным установщиком с резервной копией; неизвестные
локальные версии по-прежнему не заменяются автоматически.
